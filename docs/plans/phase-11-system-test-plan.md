# 第十一阶段系统测试计划

> 计划状态：执行中；首轮结果见 `../phase-11/system-test-progress.md`  
> 适用范围：求职邮件智能管理系统第一至第十阶段实现  
> 验收基线：`docs/requirements/mvp-scope-and-acceptance.md` 中 AC-01～AC-10  
> 真实外部服务基线：163 测试邮箱 + DeepSeek；只使用测试账户和脱敏数据

## 1. 测试目标

第十一阶段不再扩展大规模业务功能，主要确认现有系统是否达到可复现、可演示、
可解释和可恢复的毕业设计 MVP 标准：

1. 验证邮件同步、智能分析、申请管理、人工审核、日程提醒和回复发送的完整闭环。
2. 验证 UID、Message-ID、审核、状态变更、任务和 SMTP 发送的幂等边界。
3. 验证模型、邮件协议、数据库和进程异常不会被错误记录为成功。
4. 验证不可信 HTML、附件、凭据和用户资源归属的安全边界。
5. 补齐 Playwright 真实浏览器自动化，并覆盖前端主要页面和关键交互。
6. 形成可供论文测试章节引用的环境、用例、结果、缺陷和证据。

本阶段不评价大规模分类与抽取指标；Accuracy、Macro-F1、字段级 F1 和消融实验属于
第十二阶段。Outlook OAuth2、第三方日历、系统推送、多用户部署和重型任务队列仍是
增强范围。

## 3. 测试策略与环境

### 3.1 测试层级

| 层级 | 主要工具 | 目标 |
| --- | --- | --- |
| 静态检查 | Ruff、vue-tsc、Vite | 发现语法、类型、导入和生产构建问题 |
| 后端单元测试 | Pytest | Schema、状态机、解析、去重、幂等和确定性业务规则 |
| 后端集成测试 | Pytest、FastAPI TestClient、MySQL/Alembic | API、事务、迁移、Repository 和工作流恢复 |
| 前端单元测试 | Vitest | 字典、格式化、Provider、邮件 HTML 安全辅助逻辑 |
| 浏览器端到端 | Playwright Chromium | Vue、FastAPI、MySQL 联动和用户关键路径 |
| 真实外部联调 | 163、DeepSeek、IMAP/SMTP | 验证无法由 Stub 证明的协议和模型闭环 |

Playwright 第一版只以 Chromium 为强制基线；响应式布局覆盖桌面宽屏和 1280×720。
Firefox/WebKit 作为时间允许时的兼容性增强，不作为 MVP 阻断项。

### 3.2 三套环境

1. **确定性自动化环境**
   - 使用隔离的 MySQL 测试库和临时 SQLite checkpoint。
   - 使用 Stub Agent、Fake IMAP/SMTP 和脱敏 Fixture。
   - 每个用例可独立初始化和清理，不依赖执行顺序。

2. **本地集成环境**
   - 使用真实 FastAPI、Vue、MySQL 和 LangGraph checkpoint。
   - 外部模型和邮件协议可按用例选择 Stub 或测试服务。
   - 用于 Playwright、重启恢复、并发和性能测试。

3. **受控外部环境**
   - 只使用专用 163 测试邮箱和 DeepSeek 测试密钥。
   - 不使用真实个人求职邮件，不向无关地址发送邮件。
   - 会产生 SMTP、审核执行或邮件移动的用例必须记录目标、幂等键和恢复方式。

## 4. 测试数据

维护可重复使用的脱敏 Fixture，至少覆盖：

- 面试邀请、一面/二面、面试改期和面试取消。
- 笔试、在线测评、材料补充、申请进展、Offer 和拒信。
- 同公司多岗位、岗位缺失、公司别名和候选申请冲突。
- 明确时间、缺少年份、时区不明和“下周找时间”等模糊时间。
- 广告、订阅、私人邮件和其他 `NON_JOB` 邮件。
- 纯文本、HTML-only、多段 MIME、CID 图片、远程图片、按钮、附件和空正文。
- 重复 Message-ID、无 Message-ID、UIDVALIDITY 变化和重复 UID 拉取。
- 脚本、事件属性、危险协议、跟踪像素、超大附件和异常文件名。
- 模型超时、非法 JSON、Schema 不匹配和低置信度输出。

Fixture 中不得包含真实授权码、API Key、个人简历、真实会议令牌或可识别的求职隐私。

## 5. MVP 验收矩阵

| 编号 | 核心场景 | 主要自动化层级 | 通过标准 |
| --- | --- | --- | --- |
| AC-01 | 面试邀请完整闭环 | Playwright + 真实联调 | 同步、分析、两类审核、申请/日程、草稿和 SMTP 均成功且只执行一次 |
| AC-02 | 非求职邮件安全结束 | API 集成 + Playwright | 分类为 `NON_JOB`，不创建申请、任务和草稿 |
| AC-03 | 同公司多岗位冲突 | 单元 + Playwright | 显示多个候选，用户确认前不建立关联 |
| AC-04 | 模糊时间 | Agent Fixture + Playwright | 保存原文并标记待确认，不创建已确认日程 |
| AC-05 | 拒信与阶段变更 | 工作流集成 + Playwright | 拒绝审核不改状态，批准后更新并写时间线 |
| AC-06 | 同步与发送幂等 | 集成 + 并发测试 | 重复同步、审核、恢复和发送均不产生重复副作用 |
| AC-07 | 模型或外部服务失败 | 故障注入 | 状态明确、数据不丢失、修复后可安全重试 |
| AC-08 | 审核暂停与恢复 | 集成 + 进程重启 | HTTP 结束和服务重启后可恢复，重复恢复无重复动作 |
| AC-09 | 不可信 HTML 邮件 | 解析单元 + Playwright | 脚本不执行、外图默认不加载、安全正文仍可分析 |
| AC-10 | 归档与恢复 | IMAP 集成 + Playwright | 审核后移动、可恢复、重复动作幂等、求职邮件不误归档 |

若测试发现某个验收场景尚未实现，结果必须记录为“失败/功能缺口”，不得通过修改预期、
跳过断言或只展示局部接口将其标记为通过。

## 6. Playwright 端到端计划

### 6.1 基础设施

- 在 `frontend/` 增加 Playwright、配置文件和 `e2e/` 目录。
- 提供独立测试数据库初始化、Fixture 装载和 checkpoint 清理脚本。
- 使用 `webServer` 启动 FastAPI 与 Vite，禁止依赖开发者手工预先打开服务。
- 对确定性用例使用 Stub Agent 和 Fake 邮件适配器；真实外部用例使用单独标签。
- 失败时保留 trace、截图、控制台日志和必要的后端关联 ID，不保存凭据和完整隐私正文。

### 6.2 第一批强制场景

| 用例 | 场景 |
| --- | --- |
| E2E-01 | 五个核心页面可访问，侧栏、列表、详情和抽屉无页面级横向溢出 |
| E2E-02 | 邮箱 Provider 切换、保存、启用、连接测试和自动同步配置 |
| E2E-03 | 收件/已发送切换、搜索、筛选、详情、附件和安全 HTML 展示 |
| E2E-04 | 手动同步两次只新增一次，新增邮件自动进入智能处理 |
| E2E-05 | 面试邀请从分析到申请关联、阶段审核、面试任务和回复草稿 |
| E2E-06 | 审核批准、修改、拒绝三条分支及重复点击保护 |
| E2E-07 | 求职进度显示一面/二面、准确面试时间和申请时间线 |
| E2E-08 | 模糊时间与多岗位冲突进入待确认，不静默猜测 |
| E2E-09 | 服务重启后待审核工作流恢复，重复恢复无副作用 |
| E2E-10 | 邮件按钮可跳转；远程图片默认拦截，确认后加载；CID 图片自动显示 |
| E2E-11 | 日历、即将到期提醒和“知道了”已读状态 |
| E2E-12 | 空列表、接口失败、加载中和窄屏布局状态可理解且不遮挡操作 |

外部图片点击测试使用本地安全资源；不得在自动化中访问带真实跟踪令牌的第三方 URL。

## 7. 异常、恢复和并发测试

至少覆盖以下故障注入：

- 邮箱授权码错误、IMAP 超时、SMTP 明确失败和发送结果未知。
- DeepSeek 超时、限流、非法 JSON、字段缺失和 Schema 校验失败。
- 邮件正文为空、字符集错误、MIME 部分损坏和附件超过限制。
- MySQL 事务失败、checkpoint 暂时不可用和 FastAPI 进程重启。
- UIDVALIDITY 变化、Message-ID 缺失和重复同步。
- 同一审核任务并发提交、同一草稿并发发送和重复点击按钮。
- 自动同步某一账户失败后，调度线程继续处理后续周期。

每个故障用例同时断言：

1. 用户看到明确状态或错误信息。
2. 数据库未写入虚假成功状态。
3. 已完成的前置数据没有被回滚或重复创建。
4. 重试路径受控且不会重复执行外部动作。
5. 日志可通过 `run_id`、`thread_id` 或资源 ID 关联问题。

## 8. 安全测试

- 检查源码、Git 历史、日志、API 响应和前端 DOM 中不存在凭据明文。
- 验证账户读取接口只返回邮箱地址和 `credential_configured`，不返回授权码明文或密文。
- 使用 XSS Fixture 验证脚本、事件属性、表单、危险协议和 SVG 不执行。
- 验证远程图片默认无网络请求，用户确认前跟踪像素不加载。
- 验证 CID/附件只按当前用户、邮箱和邮件资源读取，非法索引返回受控错误。
- 验证超大附件、异常 MIME 类型和换行文件名不会造成执行或响应头注入。
- 验证 API 的分页、枚举、版本号、状态机和资源归属参数均受校验。
- 执行依赖漏洞检查并人工判断影响，不因无法利用的间接依赖直接判定系统失败。

## 9. 性能与稳定性目标

以下为本机单用户毕业设计 MVP 的验收目标，不代表生产 SLA：

- 准备 1,000 封邮件、200 条申请、2,000 条事件的脱敏数据集。
- 本地列表和详情 API 在数据库预热后，95% 请求不超过 500 ms。
- 页面首次进入核心页面不超过 3 秒，常规切换和筛选不出现超过 1 秒的无反馈阻塞。
- 50 封邮件的确定性解析与入库不出现重复记录或进程崩溃；模型耗时单独统计。
- 连续运行自动同步至少 60 分钟，覆盖不少于 3 个调度周期，无重复工作流和线程退出。
- 对查询接口执行 20 路并发短时测试；对审核和发送只测试竞争控制，不做破坏性压测。
- 记录模型、IMAP 和 SMTP 外部耗时，但外部网络波动不纳入本地 API 500 ms 指标。

若环境性能不足，应记录硬件、数据量、冷启动/热启动差异和瓶颈，不通过缩小数据集隐藏问题。

## 10. 回归、缺陷与退出标准

### 10.1 每轮回归命令

```text
backend:
  python -m ruff check app tests
  python -m pytest
  python -m pytest --cov=app --cov-report=term-missing
  alembic upgrade head
  alembic current

frontend:
  npm test
  npm run type-check
  npm run build
  npx playwright test
```

### 10.2 缺陷级别

- **P0**：数据破坏、凭据泄露、错误外发、审核绕过或系统无法启动。
- **P1**：AC-01～AC-10 主路径失败、重复发送/状态更新或无法恢复。
- **P2**：非核心分支错误、明显布局问题或缺少可理解反馈。
- **P3**：不影响业务完成的样式、文案和低风险兼容性问题。

### 10.3 阶段退出标准

只有满足以下条件，第十一阶段才能完成：

1. AC-01～AC-10 全部通过并有可追溯证据。
2. 后端、前端和 Playwright 全量测试连续三次通过。
3. 真实 163 增量同步、自动处理和 SMTP 幂等发送完成一次受控回归。
4. P0、P1 缺陷清零；P2 有明确处理结论；P3 可记录为已知限制。
5. 不可信 HTML、凭据、资源归属和重复外部动作的安全测试通过。
6. README 中的启动、迁移、测试和演示步骤可由干净环境复现。
7. 测试结果、修复记录和遗留风险汇总到唯一的第十一阶段进展文档。

## 11. 执行顺序与交付物

按以下顺序执行，避免真实外部联调掩盖确定性缺陷：

1. 固定环境与基线，补充覆盖率报告。
2. 补齐后端异常、并发、安全和迁移测试。
3. 建立 Playwright 基础设施并完成 E2E-01～E2E-12。
4. 执行性能、长时间自动同步和进程恢复测试。
5. 执行受控 163 + DeepSeek + SMTP 真实闭环。
6. 修复缺陷并进行三轮完整回归。
7. 输出 `docs/phase-11/system-test-progress.md`，集中记录结果、证据、缺陷和遗留风险。

阶段交付物包括：

- Playwright 配置、Fixture 和端到端测试代码。
- 新增的后端/前端自动化测试。
- 覆盖率、Playwright trace/截图、性能和安全检查结果。
- 第十一阶段唯一进展记录。
- 供论文测试章节复用的测试环境表、用例表、结果表和缺陷分析。
