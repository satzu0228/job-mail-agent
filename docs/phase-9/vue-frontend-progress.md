# 第九阶段 Vue 前端进展记录

> 记录日期：2026-07-29
> 当前状态：核心页面、多邮箱 Provider 预设、服务端查询和受控附件下载已完成，
> 已完成首轮真实数据浏览器验收

## 1. 本阶段目标

围绕前八阶段已完成的确定性业务服务和多 Agent 工作流，提供简单、清楚、
可演示的 Vue 3 操作界面。前端不直接访问 MySQL、IMAP、SMTP 或模型服务，
关键业务状态和外部动作仍由后端审核、状态机和 Executor 控制。

## 2. 已完成内容

### 2.1 前端工程

- 创建 `frontend/`，采用 Vue 3、TypeScript、Vite、Vue Router 和 Element Plus。
- 配置 `/api` 到 FastAPI `/api/v1` 的开发代理。
- 建立统一的颜色、间距、表格密度、空状态、错误提示和响应式规则。
- 使用按页面动态导入，邮件、求职进度、日程、审核和设置分别构建。

### 2.2 页面与交互

- 邮件页采用两栏结构，支持账户选择、手动同步、搜索、邮件详情、安全清洗
  HTML 展示、附件元数据、当前 AI 分析、字段证据折叠和工作流启动。
- 求职进度采用飞书表格式高密度表格，支持搜索、阶段/状态筛选、新建申请、
  详情抽屉、基本信息编辑、关联任务与邮件查看。
- 当前申请阶段在表格和详情中只读，不允许绕过人工审核直接修改。
- 审核中心区分待审核和已处理任务，展示风险、来源邮件、建议载荷，支持
  修改结构化载荷、批准和拒绝。
- `SEND_REPLY` 在批准前使用明确的二次确认，按钮文案为“确认并发送”。
- 日程页提供近期任务和月历两种视图，保留原始时间、时区、来源邮件、
  地点、会议链接和确认状态。
- 邮箱设置支持 163、126、QQ、Gmail 应用专用密码和自定义 IMAP/SMTP 预设；
  预设自动填充服务器参数，自定义模式默认展开高级设置，页面不读取或展示授权码。
- 同一用户只允许一个邮箱账户处于启用状态；切换启用账户时，后端在同一事务内
  停用其他账户，前端提供明确的启用开关。
- 增加邮件、申请、任务和审核的分页查询接口，以及完整申请事件时间线接口；
  申请详情可以读取确认后的阶段变化和其他申请事件。
- 增加受控附件下载：后端校验邮件归属、凭据、远程附件索引和大小上限，通过
  只读 IMAP 获取附件，并返回 `nosniff` 下载响应；前端不自动打开附件。

## 4. 实施中的问题与处理

### 4.1 查询接口采用兼容扩展

保留原有资源列表接口，新增返回 `items`、`total`、`offset` 和 `limit` 的查询接口，
避免破坏前八阶段已有调用方。邮件查询支持账户、关键词、申请关联、已关联状态和
分类筛选；申请、任务和审核查询支持各自核心业务筛选。前端现有列表仍可使用有界
列表，申请详情已经接入事件时间线接口。

后续在数据量增加时，可将各列表页的搜索和翻页交互逐步切换到新查询接口。

### 4.2 附件下载边界

MVP 不把附件二进制保存到 MySQL。下载时重新通过 IMAP 只读读取原邮件，并受
`email_max_message_bytes` 限制；同步时因原邮件过大而只保存头部的记录继续禁用
附件下载。邮件移动后的 UID 映射要与后续归档 Executor 一并处理。

### 4.3 安装过程出现不完整依赖

首次 `npm install` 因网络下载超过命令时限，遗留不完整的 Rollup 和 Vue language
core 文件。重新安装对应可恢复依赖后，类型检查、测试和生产构建均通过。

### 4.4 构建体积提示

Element Plus 主依赖块超过 Vite 默认 500 kB 提示线，但五个业务页面已经动态拆分。
当前单机 MVP 首屏可接受，后续可按实际加载指标决定是否增加组件级按需导入。
