# 第十阶段自动同步与提醒完成记录

> 记录日期：2026-07-30  
> 当前状态：代码、迁移、API、前端交互和自动化回归已完成

## 1. 阶段目标

将第九阶段的手动 IMAP 同步扩展为账户级定时同步，并让本次新增、解析成功的邮件
自动进入现有 LangGraph 工作流；继续以 `tasks` 作为内部日历事实源，在到期前生成
可查询、可标记已读的系统内部提醒。

第三方日历、短信、邮件和系统推送不在本阶段范围内。发送回复、修改申请阶段和创建
任务仍必须经过既有人工审核。

## 2. 已完成内容

### 2.1 自动同步

- `email_accounts` 增加自动同步开关、5～60 分钟间隔、下次执行时间和最近自动尝试时间。
- FastAPI 生命周期启动轻量轮询线程，默认每 30 秒检查一次到期账户。
- 使用 MySQL 行锁和 `SKIP LOCKED` 抢占账户，执行前推进 `next_sync_at`，避免同一数据库
  上的多个应用进程在同一轮重复同步。
- 复用原有 UID、UIDVALIDITY、Message-ID 去重和 MIME 安全解析。
- 同步结果返回新增邮件 ID；仅对本轮新增且解析成功的邮件启动现有四 Agent 工作流。
- 单个账户或单封工作流失败不会阻塞同轮其他项；详细模型错误继续写入工作流运行记录。

### 2.2 内部提醒

- 新增 `reminders` 表，通过 `task_id` 唯一约束保证一个任务至多生成一条提醒。
- 轮询周期查询仍处于待确认或已确认、且进入提醒提前量的任务。
- 提醒提供列表和已读状态 API；不复制或修改 `tasks` 中的日程事实。
- 日程页展示即将到期提醒并支持“知道了”，顶栏轮询展示未读提醒数量。

### 2.3 前端配置

- 邮箱设置页可开启/关闭自动同步，并选择 5、10、15、30 或 60 分钟间隔。
- 停用账户不能开启自动同步；运行时也只查询当前启用账户。
- 页面不读取邮箱授权码，后台同步继续通过 `credential_ref` 解析环境变量。

## 3. 数据库与配置

- Alembic 版本：`20260730_0004`
- 新增业务表：`reminders`，当前共 13 张业务表。
- 新增配置：

  - `JOB_MAIL_AUTOMATION_POLL_SECONDS`

但无需改变账户抢占字段、邮件幂等键和工作流持久化边界。

## 5. 遗留边界

- 尚未执行第十一阶段的 Playwright 真实浏览器端到端测试。
- 本轮没有使用真实邮箱等待 5～10 分钟进行长时间自动轮询验收；真实 IMAP/SMTP
  基线仍沿用第四、第八阶段已通过的 163 邮箱闭环。
- 进程崩溃后无需恢复内存线程；重启后根据 MySQL `next_sync_at` 继续轮询。若崩溃发生
  在账户抢占后、IMAP 请求前，本轮会延迟到下个同步间隔，而不会高频重试邮箱。
- 外部日历、`.ics` 导出和通知推送仍属于后续增强范围。
